# Telegram Reminder Bot

Telegram-бот напоминаний: одноразовые и повторяющиеся (еженедельно/ежемесячно)
напоминания, получатели — сам пользователь или подтверждённый друг, доставка с
повторами при временных ошибках Telegram. Дополнительно — ежедневный трекер
привычек с напоминанием в выбранное локальное время и статистикой, списки задач
(ToDo) и списки желаний с совместным доступом и безопасными ссылками.

Проект рассчитан на **один Node.js-процесс на VPS рядом с PostgreSQL**:
long polling Telegram + планировщик `node-cron` каждую минуту. Vercel, Redis и
очереди не используются.

## Стек

- Node.js 20+, TypeScript
- grammY (Telegram Bot API)
- `pg` (параметризованный SQL, без ORM в рантайме)
- `node-cron` — планировщик каждую минуту
- luxon — часовые пояса и DST
- zod — валидация env и данных
- Next.js — только опциональные HTTP-эндпоинты (`/api/health`, webhook, cron)

## Быстрый старт (локально)

```bash
npm ci
cp .env.example .env
# заполнить DATABASE_URL и TELEGRAM_BOT_TOKEN
npm run bot:start
```

Проверки:

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

`npm test` запускает unit-тесты. Интеграционные тесты привычек и списков
подключаются к отдельной тестовой PostgreSQL через `TEST_DATABASE_URL` и
пропускаются, если переменная не задана:

```bash
TEST_DATABASE_URL='postgresql://user:pass@127.0.0.1:5432/telegram_habits_test' npm test
```

Подготовка отдельной тестовой базы (имена/пароль — локальные, не для прода):

```bash
sudo -u postgres psql -c "CREATE ROLE habits_test LOGIN PASSWORD 'habits_test'"
sudo -u postgres createdb -O habits_test telegram_habits_test
psql 'postgresql://habits_test:habits_test@127.0.0.1:5432/telegram_habits_test' \
  -v ON_ERROR_STOP=1 -f deploy/schema.sql
```

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `DATABASE_URL` | да | `postgresql://user:pass@127.0.0.1:5432/telegram_reminders` |
| `TELEGRAM_BOT_TOKEN` | да | токен от @BotFather |
| `BOT_MODE` | нет | `polling` (по умолчанию) или `webhook` |
| `TELEGRAM_WEBHOOK_SECRET` | для webhook | секрет заголовка Telegram |
| `CRON_SECRET` | нет | защита HTTP-cron роута (если используется Next.js) |
| `APP_BASE_URL` | нет | внешний URL для webhook |
| `LOG_LEVEL` | нет | `debug` / `info` / `warn` / `error` |
| `REMINDER_BATCH_SIZE` | нет | по умолчанию 25 |
| `DELIVERY_BATCH_SIZE` | нет | по умолчанию 50 |
| `MAX_DELIVERY_ATTEMPTS` | нет | по умолчанию 5 |

## Как работает планировщик

Один процесс (`src/bot/index.ts`) каждую минуту (`* * * * *`):

1. Освобождает просроченные lease-блокировки.
2. Забирает до `REMINDER_BATCH_SIZE` напоминаний с `next_run_at <= now` и
   `status = ACTIVE`, ставит им `claim_token`.
3. Создаёт запись `reminder_occurrences` (уникальность `reminder_id + scheduled_at`).
4. Создаёт `reminder_deliveries` для владельца и подтверждённых друзей
   (уникальность `occurrence_id + recipient_user_id`).
5. Одноразовое напоминание переводит в `COMPLETED`, повторяющееся — вычисляет
   следующий запуск в его часовом поясе (DST учитывается).
6. Забирает до `DELIVERY_BATCH_SIZE` доставок (`PENDING`/`RETRYABLE`), отправляет
   и фиксирует `SENT`, `RETRYABLE` (с экспоненциальным backoff) или `PERMANENT`.
7. Синхронизирует статус occurrence с доставками.
8. Отправляет ежедневные напоминания о привычках не чаще одного раза на
   локальный календарный день пользователя. День «занимается» условным
   `UPDATE last_notified_date` до отправки, поэтому перезапуск процесса и
   пересекающиеся запуски cron не создают дублей. Промпт не отправляется, если
   у пользователя нет активных привычек или напоминание выключено.

Статусы доставки: `PENDING`, `PROCESSING`, `SENT`, `RETRYABLE`, `PERMANENT`,
`SKIPPED`. Permanent-ошибки (403/400 от Telegram) не ретраятся бесконечно.

## Главное меню

- Главное меню содержит только верхнеуровневые разделы: «Мои напоминания»,
  «Мои привычки», «Списки задач», «Списки желаний», «Друзья» и «Настройки».
  Кнопки расположены по две в ряд, чтобы меню оставалось компактным.
- Создание напоминания находится внутри раздела «Мои напоминания» и доступно
  также при пустом списке.
- Статистика привычек находится внутри раздела «Мои привычки».

## Напоминания: время и минуты

- Для новых напоминаний минуты выбираются только из четырёх значений: `00`,
  `15`, `30`, `45`. Это ограничение действует и на стороне клавиатуры, и при
  разборе callback-данных.
- Уже сохранённые напоминания не переписываются: если в базе было, например,
  `09:07`, оно продолжит срабатывать в `09:07`. Ограничение касается только
  новых выборов времени.
- У напоминаний о привычках минуты по-прежнему выбираются свободно (все `00..59`),
  чтобы не менять поведение трекера.

## Списки задач и желаний

Кнопки «📝 Списки задач» и «🎁 Списки желаний» находятся в главном меню.

- У каждого пользователя автоматически создаётся личный список по умолчанию:
  «Мои задачи» или «Мои желания». Он показывается первым и не удаляется.
  Дополнительные личные списки можно создавать, переименовывать и удалять.
- Списки друзей показываются после личных. Доступ к чужому списку возможен
  только после подтверждённой дружбы.
- **Задачи.** Элемент содержит название (до 200 символов), описание (до 2000) и
  необязательную ссылку. Владелец может переименовать/удалить список и выдать
  другу доступ `READ` (только чтение) или `EDIT` (изменение задач). Друг с
  `EDIT` может добавлять, редактировать, отмечать выполненными и удалять задачи,
  но не может переименовывать/удалять сам список или передавать его дальше.
- **Желания.** Элемент содержит название, описание и необязательную ссылку.
  Совместный доступ всегда `READ`: друг видит список и элементы, но менять их
  может только владелец.
- При удалении друга доступ к совместным спискам в обе стороны отзывается в той
  же транзакции, что и удаление дружбы. Сами списки и их содержимое сохраняются у
  владельцев.
- Все операции проверяют доступ на сервере по `user_id` из Telegram-профиля, а не
  по данным callback. Подделанный или устаревший callback не даёт прав.
- Списки и элементы листаются постранично; callback-данные содержат только
  числовые идентификаторы и укладываются в лимит Telegram 64 байта.

### Добавление элементов

- В открытом списке, который доступен для изменения, есть одна кнопка
  «➕ Добавить задачу» или «➕ Добавить желание». Она открывает ввод списком —
  отдельного интерфейса для добавления по одному нет. Форма редактирования
  существующих элементов не изменилась.
- Отправьте одну задачу/желание или несколько, по одному на строку. Пустые
  строки игнорируются, порядок элементов сохраняется.
- В начале строки автоматически удаляются распространённые маркеры списка:
  `1.`, `1)`, `-`, `*`, `•`, `☐`, `□`, `[ ]`, `[x]`. Удаляются только маркеры в
  начале строки, поэтому числа, дефисы и другая пунктуация внутри текста и URL
  не затрагиваются.
- Первая `http(s)`-ссылка в строке сохраняется отдельно и выводится
  кликабельной; оставшийся текст становится названием. Пользовательский текст
  по-прежнему экранируется как HTML.
- Массовое добавление подчиняется тем же правам: в задачах могут добавлять
  владелец и друг с `EDIT`, в желаниях — только владелец. Совместные списки
  желаний остаются доступными только для чтения.
- За одно сообщение можно добавить до 100 элементов. Слишком длинные или
  некорректные строки не теряются молча: бот показывает номера таких строк и
  причину, а корректные элементы сохраняет одной транзакцией.

### Ссылки и форматирование

- Принимаются только абсолютные `http://` и `https://` ссылки. Схемы вроде
  `javascript:`, `data:`, `file:` и относительные адреса отклоняются с
  подсказкой.
- Ссылка сохраняется и выводится кликабельной в HTML-режиме Telegram. Весь
  пользовательский текст (названия, описания, имена) экранируется, поэтому
  `<`, `>`, `&` и кавычки не ломают разметку.
- Отправьте `-`, чтобы пропустить или очистить описание/ссылку.

## Одно основное сообщение интерфейса

- Бот хранит идентификатор одного «основного» сообщения для каждой пары
  пользователь/чат в таблице `ui_state`. Навигация по меню, спискам и диалогам
  редактирует это сообщение, а не отправляет новое на каждый шаг.
- Если сообщение было удалено вручную, стало слишком старым для редактирования
  или Telegram вернул ошибку, бот отправляет замену и запоминает новый
  идентификатор. Ответ «message is not modified» считается успешным
  редактированием.
- Ограничение: в чате поддерживается одно основное сообщение. Промежуточные
  подсказки тоже используют его, поэтому история чата не сохраняет каждый экран.
  При ручном удалении основного сообщения следующий экран просто создаст новое.
- Запланированные напоминания и уведомления другим пользователям отправляются
  отдельными сообщениями и не зависят от состояния интерфейса. Планировщик
  использует собственный sender, поэтому сбой редактирования UI не влияет на
  доставку.

## Трекер привычек

Кнопка «Мои привычки» находится в главном меню; статистика открывается внутри
этого раздела.

- Привычек может быть любое количество; название — обычный текст до 100
  символов, обрезается по краям, внутренние пробелы схлопываются.
- Ежедневная отметка хранится как календарная дата в часовом поясе пользователя,
  уникальность `(habit_id, completion_date)` не даёт создать дубль. Callback
  содержит желаемое состояние, поэтому повторная доставка update не переключает
  отметку дважды.
- Удаление — мягкое (`is_active = false`): привычка исчезает из трекинга и
  статистики, история отметок сохраняется.
- «Готово на сегодня» только закрывает экран и **не** отмечает невыбранные
  привычки; каждая отметка сохраняется сразу при нажатии.
- Время ежедневного напоминания задаётся в часах и минутах и сохраняется вместе с
  флагом включения. Используется `users.time_zone` (fallback `UTC`). После
  смены часового пояса время трактуется в новом поясе.
- Неделя начинается с понедельника. Знаменатель считается только по прошедшим
  дням: с даты создания привычки (или начала недели, если она создана раньше) по
  сегодня включительно. Будущие даты и удалённые привычки в статистику не
  попадают. Процент округляется до одного знака после запятой.

## База данных

Схема: [`deploy/schema.sql`](deploy/schema.sql). Таблицы:

`users`, `reminders`, `reminder_recipients`, `friend_requests`, `friendships`,
`reminder_occurrences`, `reminder_deliveries`, `conversation_states`, `habits`,
`habit_completions`, `habit_reminder_settings`, `todo_lists`, `todo_items`,
`todo_list_shares`, `wish_lists`, `wish_list_items`, `wish_list_shares`,
`ui_state`.

Для существующей базы обновление схемы выполняется версионированными SQL-миграциями
из [`deploy/migrations`](deploy/migrations). Все миграции аддитивны и
идемпотентны:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f deploy/migrations/20261025_habits.up.sql

psql "$DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f deploy/migrations/20261026_lists.up.sql
```

Миграция списков создаёт таблицы ToDo/Wish, доступы и `ui_state`; существующие
напоминания, привычки, дружба и пользователи не изменяются. Повторный запуск
безопасен. Откат удаляет только таблицы списков и состояние интерфейса:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f deploy/migrations/20261026_lists.down.sql

psql "$DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f deploy/migrations/20261025_habits.down.sql
```

> В этом проекте реальная схема ведётся через `deploy/schema.sql` и SQL-миграции,
> а не через `prisma migrate deploy`: Prisma-схема не отражает фактическую
> snake_case-схему продакшена. Не применяйте к рабочей базе `prisma migrate`.

Создание БД и пользователя (пример):

```bash
sudo -u postgres psql <<'SQL'
CREATE ROLE telegram_reminders_app LOGIN PASSWORD '...';
CREATE DATABASE telegram_reminders OWNER telegram_reminders_app;
SQL

sudo -u postgres psql -d telegram_reminders -f deploy/schema.sql
```

Для чистой установки `deploy/schema.sql` уже содержит таблицы привычек, списков
задач/желаний и `ui_state`; отдельно применять миграции не нужно. Применение
миграций поверх свежей схемы безопасно — все объекты создаются через
`IF NOT EXISTS`.

Приложение использует только `DATABASE_URL`; серверный конфиг PostgreSQL менять
не нужно.

## Установка на VPS (systemd)

```bash
# 1. Пользователь и каталог
useradd --system --home /opt/telegram-reminder-bot --shell /usr/sbin/nologin reminderbot || true
mkdir -p /opt/telegram-reminder-bot /etc/telegram-reminder-bot

# 2. Код (rsync с локальной машины)
rsync -a --delete \
  --exclude node_modules --exclude .next --exclude .git \
  ./ root@SERVER:/opt/telegram-reminder-bot/

# 3. Зависимости (tsx нужен для запуска TypeScript)
cd /opt/telegram-reminder-bot
npm ci --include=dev

# 4. Окружение
install -m 600 deploy/bot.env.example /etc/telegram-reminder-bot/bot.env
# отредактировать /etc/telegram-reminder-bot/bot.env
chown root:reminderbot /etc/telegram-reminder-bot/bot.env

# 5. systemd
install -m 644 deploy/telegram-reminder-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now telegram-reminder-bot
journalctl -u telegram-reminder-bot -f
```

`deploy/bot.env.example` — тот же набор переменных, что в `.env.example`.

После добавления токена:

```bash
systemctl restart telegram-reminder-bot
journalctl -u telegram-reminder-bot -n 100 --no-pager
```

## Режим webhook (опционально)

По умолчанию используется long polling. Если нужен webhook, поднимите Next.js
(`npm run start`) и выполните:

```bash
BOT_MODE=webhook TELEGRAM_WEBHOOK_SECRET=... APP_BASE_URL=https://... npm run webhook:set
```

HTTP-cron роут (`/api/cron/process-reminders`) оставлен для совместимости, но на
VPS он не нужен: планировщик работает внутри процесса бота.

## Структура

```
src/bot/index.ts             точка входа: cron + long polling
src/lib/scheduler/           claim/lease, создание occurrence/delivery, backoff
src/lib/scheduler/habits.ts  ежедневные напоминания о привычках
src/lib/bot/lists.ts        сценарии ToDo/Wish: CRUD, доступы, совместное использование
src/lib/telegram/primaryUi.ts  редактирование одного основного сообщения интерфейса
src/lib/telegram/listsRender.ts  экранирование и рендер списков, безопасные ссылки
src/lib/habits/stats.ts      локальные даты, границы недели, проценты
src/lib/bot/dispatcher.ts    обработка update: команды, callback, диалоги
src/lib/services/            SQL-сервисы (users, friends, reminders, habits, lists, workflows)
src/lib/telegram/            grammY sender, клавиатуры, callback-парсер, рендер
src/lib/time.ts              часовые пояса, DST, следующее срабатывание
src/lib/i18n/ru.ts           все пользовательские строки
```
